第一部分：项目初始化与基础设施
═══════════════════════════════════════════════════════════════

一、项目初始化 — Maven 多模块脚手架搭建

1.1  项目目录全览（9 个子模块 + specs + docker + .claude）
1.2  Maven 根 POM 配置：版本统一管理（JDK 21 / Spring Boot 3.5.x / AgentScope 2.0.0）
1.3  子模块划分原则：一个 Agent = 一个模块，Skills 独立共享，Server 统一入口
1.4  Maven Wrapper 锁定构建工具版本
1.5  .editorconfig + Checkstyle（Alibaba Java Coding Guidelines）+ PMD 静态分析
1.6  Docker Compose 本地基础设施：Nacos 3.1.0 + Redis 7.x 一键启动
1.7  Git 提交规范：<type>(<scope>): <TASK-ID> <描述>（Conventional Commits）

二、SDD 规范驱动开发体系搭建

2.1  SPECIFY → PLAN → TASKS → IMPLEMENT 四阶段工作流概述
2.2  specs/ 目录规范：constitution.md（宪章）+ architecture.md（ADR）+ 方法论 + features/
2.3  specs/features/<NNN-feature>/ 按功能组织：spec.md → design.md → tasks.md
2.4  CLAUDE.md 作为 AI 协作入口（~100 行地图模式，按需加载详细文档）
2.5  .claude/commands/ 自定义命令：/spec /plan /tasks /implement /review
2.6  .claude/settings.json 权限策略：Allow Maven/Docker/Git，Deny rm/sudo/.env

三、Harness Engineering 七层约束架构

3.1  层1 项目搭建层：JDK/Maven/Docker 版本锁定 + .java-version + Maven Wrapper
3.2  层2 上下文工程层：CLAUDE.md → specs/ 按需加载，ReMe 双层记忆（Redis + 向量DB）
3.3  层3 约束防护层：ArchUnit 架构测试 + Guava RateLimiter + AgentScope 安全沙箱
3.4  层4 多Agent架构层：防死锁（调用深度≤5）+ Agent 状态机（IDLE→THINKING→ACTING→OBSERVING→DONE）
3.5  层5 评估反馈层：OutputQualityGate 质量门禁 + 用户反馈闭环 → ReMe 长期记忆
3.6  层6 长任务层：Session 持久化 + PlanNotebook 断点续传 + 任务生命周期管理
3.7  层7 诊断工具层：OpenTelemetry 链路追踪 + Micrometer→Prometheus 指标 + 结构化 JSON 日志

═══════════════════════════════════════════════════════════════

四、5 个 Agent 角色设计与职责定义

4.1  主管 Agent（SupervisorAgent）— PlanNotebook 任务分解 + A2A 委派 + 结果汇总
4.2  小红书分析 Agent（XHSAnalysisAgent）— 笔记搜索→内容提取→情感分析→RAG 增强
4.3  路线规划 Agent（RouteAgent）— 百度/高德 MCP → 距离计算 → 路线排序 → 交通优化
4.4  行程编排 Agent（ItineraryAgent）— 景点推荐 → 时间槽分配 → 餐饮安排 → PDF 导出
4.5  费用统筹 Agent（BudgetAgent）— 费用估算 → 预算检查 → 超支预警（≥15% 触发 HITL）

五、主管 Agent 自主分解复杂任务

5.1  三种调度模式自适应切换：Pipeline（简单）→ StateGraph（分支）→ PlanNotebook（复杂）
5.2  PlanNotebook 自主规划机制：任务拆解 → 步骤生成 → 并行/串行调度
5.3  Hook 拦截技术：关键节点人工介入（HITL）— 超预算/天数不匹配/评分过低
5.4  子任务分发：A2A 协议 + Msg 不可变消息 + 超时重试 + 降级默认值
5.5  结果汇总与冲突仲裁：多 Agent 产出物合并 → OutputQualityGate 质量门禁

六、A2A 协议 + Nacos 服务注册与发现

6.1  A2A（Agent-to-Agent）协议：消息格式（Protobuf）、同步/异步调用模式
6.2  Nacos 注册中心：Agent 启动自动注册 → 健康检查 → 心跳保活
6.3  主管 Agent 通过 AgentRegistry 动态获取可用子 Agent 列表
6.4  MsgHub 消息总线：Agent 间一对多广播 + 点对点请求/响应
6.5  MCP（Model Context Protocol）：百度/高德地图作为外部 MCP Server 接入
6.6  Agent 下线处理：Nacos 健康检查失败 → 自动摘除 → 任务重新分发
